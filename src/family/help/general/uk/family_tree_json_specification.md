# Специфікація JSON-файлу родинного дерева

## 1. Огляд

Цей документ описує формат JSON-файлу, у якому зберігаються генеалогічні дані родинного дерева. Формат дозволяє зберігати записи осіб із біографічними відомостями та записи зв'язків, що визначають родинні відносини.

## 2. Структура верхнього рівня

JSON-файл містить три ключі верхнього рівня:

| Ключ | Тип | Опис |
|------|-----|------|
| persons | Масив | Масив об'єктів Person з біографічними даними |
| relations | Масив | Масив об'єктів Relation, що визначають родинні відносини |
| version | Рядок | Версія формату файлу (наприклад, "0.0.1") |

## 3. Об'єкт Person (Особа)

Кожна особа в родинному дереві представлена об'єктом Person з такою структурою:

### 3.1 Поля об'єкта Person

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| id | Рядок (UUID) | Так | Унікальний ідентифікатор особи |
| name | Об'єкт Name | Ні | Відомості про ім'я особи |
| sex | Рядок | Ні | Стать: "male", "female" або "other" |
| birth | Об'єкт Event | Ні | Дата та місце народження |
| death | Об'єкт Event | Ні | Дата та місце смерті |
| picture | Об'єкт Picture | Ні | Фотографія особи, закодована в Base64 |
| text | Рядок | Ні | Нотатки або біографія, закодовані в Base64 |

### 3.2 Об'єкт Name (Ім'я)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| first-name | Рядок | Ні | Ім'я особи |
| last-name | Рядок | Ні | Прізвище особи |
| middle-name | Рядок | Ні | По батькові або друге ім'я особи |
| maiden-name | Рядок | Ні | Дівоче прізвище (якщо змінилося після шлюбу) |

### 3.3 Об'єкт Event (Подія - Народження/Смерть/Початок і кінець зв'язку)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| date | Об'єкт Date | Ні | Дата події |
| place | Об'єкт Place | Ні | Місце події |

### 3.4 Об'єкт Date (Дата)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| year | Ціле число | Так | Рік (наприклад, 1985) |
| month | Ціле число | Ні | Місяць (1-12), пропускається, якщо невідомий |
| day | Ціле число | Ні | День місяця (1-31), пропускається, якщо невідомий |
| fuzzy | Boolean | Ні | True, якщо дата приблизна/неточна, false, якщо пропущено |

Пропустіть `day`, якщо відомі лише місяць і рік, і пропустіть і `day`, і `month`, якщо відомий лише рік.

### 3.5 Об'єкт Place (Місце)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| address | Об'єкт Address | Ні | Структуровані відомості про адресу |
| geo-coordinate | Об'єкт Geo Coordinate | Ні | Географічне розташування |

### 3.6 Об'єкт Address (Адреса)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| city | Рядок | Ні | Назва міста або населеного пункту |
| country | Рядок | Ні | Назва країни |
| street | Рядок | Ні | Назва вулиці |
| street-number | Рядок | Ні | Номер будинку |
| postal-code | Рядок | Ні | Поштовий індекс |

### 3.6.1 Об'єкт Geo Coordinate (Географічні координати)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| latitude | Число | Ні | Широта в градусах |
| longitude | Число | Ні | Довгота в градусах |
| altitude | Число | Ні | Висота в метрах |

### 3.7 Об'єкт Picture (Зображення)

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| title | Рядок | Ні | Назва зображення |
| description | Рядок | Ні | Опис зображення |
| url | Рядок | Ні | Шлях до файлу зображення відносно файлу родинного дерева |
| base64Data | Рядок | Ні | Дані зображення, закодовані в Base64 (формат PNG) |

Саме зображення зберігається або в окремому файлі, на який посилається `url`,
або вбудовується у файл дерева як `base64Data`.

Якщо `url` задано, шлях обчислюється відносно каталогу, що містить файл
родинного дерева, і має вказувати на файл у цьому каталозі або нижче. Шляхи, що
виходять за його межі (наприклад `../foto/ivan.png` або шлях на іншому диску),
відхиляються, і зображення натомість вбудовується як `base64Data`. Зображення,
успішно збережене в окремому файлі, не містить `base64Data`.

## 4. Об'єкт Relation (Зв'язок)

Зв'язки визначають родинні відносини між особами. Кожен зв'язок представляє партнерство (шлюб або подібний союз) і за потреби перелічує дітей, народжених у цьому партнерстві.

### 4.1 Поля об'єкта Relation

| Поле | Тип | Обов'язкове | Опис |
|------|-----|-------------|------|
| id | Рядок (UUID) | Так | Унікальний ідентифікатор зв'язку |
| partners | Масив\<UUID\> | Ні | Масив ID осіб (зазвичай 2 партнери), партнери є також батьками дітей |
| children | Масив\<UUID\> | Ні | Масив ID осіб дітей |
| begin | Об'єкт Event | Ні | Початок зв'язку (наприклад, дата шлюбу) |
| end | Об'єкт Event | Ні | Кінець зв'язку (наприклад, дата розлучення) |

## 5. Приклад

Нижче наведено приклад мінімального родинного дерева з двома особами та одним зв'язком:

```json
{
  "version": "0.0.1",
  "persons": [
    {
      "id": "a1b2c3d4-e5f6-4789-abcd-ef1234567890",
      "name": { "first-name": "John", "last-name": "Smith" },
      "sex": "male",
      "birth": {
        "date": { "day": 15, "month": 6, "year": 1980, "fuzzy": false },
        "place": { "address": { "city": "Prague", "country": "Czech Republic" } }
      }
    },
    {
      "id": "b7c8d9e0-f1a2-4b3c-8d4e-5f6a7b8c9d0e",
      "name": { "first-name": "Jane", "last-name": "Smith", "maiden-name": "Doe" },
      "sex": "female"
    }
  ],
  "relations": [
    {
      "id": "c3d4e5f6-a7b8-4c9d-9e0f-1a2b3c4d5e6f",
      "partners": ["a1b2c3d4-e5f6-4789-abcd-ef1234567890", "b7c8d9e0-f1a2-4b3c-8d4e-5f6a7b8c9d0e"],
      "children": [],
      "begin": { "date": { "day": 20, "month": 8, "year": 2010, "fuzzy": false } }
    }
  ]
}
```

## 6. Примітки щодо реалізації

**Формат ID:** Усі ідентифікатори використовують формат UUID v4 (наприклад, "4e28b000-0c04-434a-9382-792ea3543316").

**Посилальна цілісність:** Усі посилання UUID у масивах partners і children мають відповідати дійсним ID осіб у масиві persons.

**Кількість партнерів:** Більшість зв'язків має рівно 2 партнери, але формат підтримує 0, 1 або 2 партнери для неповних записів або сімей з одним із батьків.

**Кодування символів:** Файл використовує кодування UTF-8 для підтримки міжнародних символів в іменах і назвах місць.

**Поля Base64:** Поля text і picture.base64Data містять вміст, закодований у Base64, щоб безпечно зберігати двійкові дані та форматований текст у JSON.
